本次删除旧 v2/v3 主线数据，使用 `csv_v2/v100/*.csv` 重新生成新的 v2 数据集。

当前主线数据切换为：

| 项目 | 路径 |
| --- | --- |
| extracted | `data/extracted_v2` |
| scaled | `data/scaled_v2` |

## 生成命令

Extract 使用 `.vscode/launch.json` 中 `extract` 任务的同款模块调用，只把输入和输出定为 v2：

```bash
PYTHONPATH=src uv run python -m gnn_model.data.extract \
  --csv_dir csv_v2/v100 \
  --output_dir data/extracted_v2
```

Scaler 使用 `.vscode/launch.json` 中 `scaler` 任务的同款目标字段：

```bash
PYTHONPATH=src uv run python -m gnn_model.data.scaler \
  --data_dir data/extracted_v2 \
  --scaler_output_path data/scalers_v2 \
  --scaled_data_output_path data/scaled_v2 \
  --target_fields duration_sec_avg,cpu_cores_p95,memory_delta_gb_p95,gpu_util_percent_p95,gpu_sm_active_percent_p95,gpu_sm_occupancy_percent_p95,gpu_mem_used_mb_p95
```

## 输入与过滤

| 项目 | 数量 |
| --- | ---: |
| CSV files | 23 |
| raw CSV rows | 20,359 |
| Qwen3.5 rows excluded before ONNX extraction | 36 |
| rows before GPU quality filter | 20,323 |
| GPU quality filtered rows | 162 |
| high-memory-delta observations | 557 |
| final graph rows | 20,143 |

Qwen3.5 行仍然无法进入当前 `onnx_tool` 抽取路径：其 BFLOAT16 `Constant` tensor 会触发 `onnx_tool` 解析错误 `buffer size must be a multiple of element size`。因此 `gnn_model.data.extract` 中正式过滤 `base_model_name` 以 `Qwen3.5` 开头的行。

本次为支持 `csv_v2/v100` 中的 LLM CSV，同步补齐了当前 v100 图实际出现的 ONNX op 分类，并注册 `IsNaNNode`。新 schema 不再使用 `op_other` fallback，未知 op 会直接失败，避免静默吞掉新算子。
