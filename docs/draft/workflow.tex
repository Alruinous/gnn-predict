\subsection{GNN 调度算法}

系统在 workflow DAG 初始化时，会 根据每一个节点所需的模型，维护一个模型资源池。节点使用该模型运行推理服务，视作引用在模型。比如模型的需求分别为 qwen3-8b 、 qwen3-4b 、 qwen3-4b ，那么就会维护一个 qwen3-8b 的引用和两个 qwen3-4b 的引用。系统在初始化时会预存几类模型的图特征、部署耗时等指标，供 GNN 预测器使用。

目前 GNN 预测器支持根据模型图结构，输入 token 长度和输出 token 长度，构建图特征，预测模型的 prefill 和 decode 耗时、显存峰值等指标。

本文区分 task、session 和 model instance 三类对象。Task 是实际被调度执行的单位，表示某个 session 在某个 workflow 节点上的一次执行请求；session 表示同一个输入任务在 DAG 中传播形成的依赖上下文；model instance 表示已经部署在加速卡上的模型副本，是资源管理单位。Session 不独占模型，也不直接决定模型释放，只用于判断 task 依赖是否齐全、估计下游 task 的 ready 时间和 token 规模。

算法采用 loop 扫描方式实现，每轮调度器按照拓扑顺序扫描 workflow DAG，并从节点队列与 session 状态中收集候选 task。如果一个节点的前驱节点执行推理任务，则根据前驱节点的推理任务开始时间，和预测器提供的预计总耗时，推算前驱节点完成当前任务的结束时间。根据该结束时间，可以知道当前节点的推理任务预计何时开始。

如果节点内的模型已部署且引用的模型正空闲，当任务到来时，则可以立即运行该推理任务。如果节点内的模型没有部署，或已部署的模型正在被另一节点使用（多个引用一个实例模型的情况），则可以根据前驱节点的 ETA 和当前节点所需模型的部署耗时，考虑提前加载一个新的模型到一个加速卡上。模型资源池需要维护每个模型的使用状态。

前驱推理节点的预计输出 token 长度可以由当前输入 token 长度和历史平均输出 token 长度的信息预测出，再结合当前节点的 prompt template，节点的输入 token 长度也可以被计算出一个预计值。根据该预计值、节点模型图结构和预计输出 token 的长度，可以预测出节点模型的显存峰值。根据最大适配或最小适配原则，将模型部署到一个合适的加速卡上。如果缺少合适的加速卡，则可以考虑驱逐合适的空闲模型。

驱逐策略只能驱逐空引用的模型，这种模型处于 idle 状态，只能驱逐显存容量大于等于待部署的模型，这样模型才能成功部署。在此必要条件下，策略又可以分驱逐显存开销最大、驱逐显存开销最小、驱逐空闲时间最长、驱逐空闲时间最短。驱逐策略使用的显存开销值，为模型 idle 时占用的实际显存开销，而非预测器预测的。

如果缺少合适的空闲模型可驱逐，则节点无法立刻运行推理任务。该类节点的模型部署会在下一轮调度被再次考虑，因此节点的推理任务可能会被缓存到 buffer 中，等待下一轮调度。从缓存中消费任务的策略不做研究，固定为 FIFO。

\begin{algorithm}[htbp]
    \caption{Prediction-Aware Workflow Scheduling Algorithm}
    \label{alg:gnn_scheduler}

    \KwIn{Workflow DAG $\mathcal{G}=(\mathcal{V}, \mathcal{E})$, accelerator set $\mathcal{K}$, model pool $\mathcal{P}$, GNN predictor $f_{GNN}$}
    \KwOut{Task dispatch, model loading/prefetch, accelerator placement, and eviction decisions}

    Initialize workflow state $\mathcal{S}$ and model pool $\mathcal{P}$\;

    \While{System is running}{
        $t_{now} \gets$ GetCurrentTime()\;
        $\mathcal{C}_{ready} \gets$ CollectReadyTasks($\mathcal{G}, \mathcal{S}$)\;
        $\mathcal{C}_{near} \gets$ CollectNearReadyTasks($\mathcal{G}, \mathcal{S}$)\;
        $\mathcal{C} \gets \mathcal{C}_{ready} \cup \mathcal{C}_{near}$\;

        \For{each candidate task $x=(s,v) \in \mathcal{C}$ in topological order}{
            $\mathcal{M}_v \gets$ Required model specification for node $v$\;
            $\hat{t}_{ready}(x) \gets$ EstimateReadyTime($x, \mathcal{S}$)\;
            $\hat{L}_{in}(x), \hat{L}_{out}(x) \gets$ PredictTokens($x, \mathcal{S}$)\;
            $M_{peak}(x), T_{infer}(x) \gets f_{GNN}\left(F(\mathcal{M}_v), \hat{L}_{in}(x), \hat{L}_{out}(x)\right)$\;

            \If{$x \in \mathcal{C}_{ready}$}{
                $m \gets$ SelectIdleInstance($\mathcal{P}, \mathcal{M}_v$)\;
                \If{$m \neq \emptyset$}{
                    Dispatch($x, m$)\;
                    \textbf{continue}\;
                }
            }

            $T_{deploy} \gets$ GetDeployTime($\mathcal{M}_v$)\;
            \If{$t_{now} + T_{deploy} + \epsilon_{time} \ge \hat{t}_{ready}(x)$}{
                $k^* \gets$ SelectAccelerator($\mathcal{K}, M_{peak}(x) + \epsilon_{mem}$)\;

                \If{$k^* = \emptyset$}{
                    $\mathcal{P}_{evict} \gets$ EvictPolicy($\mathcal{P}, M_{peak}(x) + \epsilon_{mem}$)\;
                    \If{$\mathcal{P}_{evict} \neq \emptyset$}{
                        Evict($\mathcal{P}_{evict}$)\;
                        $k^* \gets$ SelectAccelerator($\mathcal{K}, M_{peak}(x) + \epsilon_{mem}$)\;
                    }
                }

                \If{$k^* \neq \emptyset$}{
                    LoadOrPrefetch($\mathcal{M}_v, k^*$)\;
                }
            }
        }
        Sleep($\Delta t$)\;
    }
\end{algorithm}

\subsubsection*{符号说明与核心模块定义}

算法 \ref{alg:gnn_scheduler} 中涉及的核心符号与函数定义如下：

\begin{itemize}
    \item \textbf{图模型与节点资源}：
    \begin{itemize}
        \item $\mathcal{G}=(\mathcal{V}, \mathcal{E})$：表示多智能体工作流的 DAG（有向无环图），其中 $\mathcal{V}$ 为智能体节点集合，$\mathcal{E}$ 为节点间的数据与执行依赖边。
        \item $x=(s,v)$：候选 task，其中 $s$ 为 session，$v$ 为 workflow 节点。
        \item $\mathcal{M}_v$：节点 $v$ 运行所需的具体大语言模型规格（如 \texttt{qwen3-8b}）。
        \item $\mathcal{K}$：系统中可用的本地加速卡（如 GPU）集合。
        \item $\mathcal{P}$：全局模型资源池，维护所有已加载到显存中的模型实例及其运行时状态（如：所属设备、是否处于空闲 $Idle$ 状态、实际闲置显存等）。
        \item $\mathcal{S}$：workflow 运行状态，包括 session 依赖状态、节点队列积压、任务开始时间和预计完成时间。
    \end{itemize}

    \item \textbf{时间与预测指标}：
    \begin{itemize}
        \item $t_{now}$：当前系统的绝对时间。
        \item $\Delta t$：调度器的轮询间隔（Sleep Gap），用于避免高频扫描带来的 CPU 额外开销。
        \item $\hat{t}_{ready}(x)$：task $x$ 所需前置任务全部就绪的预计最早开始时间。对于 fan-in 节点，其由同一 session 下前驱 task 的预计完成时间推算得出。
        \item $T_{deploy}$：模型 $\mathcal{M}_v$ 从外部存储加载到加速卡显存中所需的预计部署耗时。
        \item $\epsilon_{time}, \epsilon_{mem}$：调度系统的安全裕度（Safety Margin）参数。前者代表提前加载触发的时间容错边界；后者代表显存预测的安全防线，用以规避长尾或极值序列引发的 OOM。
    \end{itemize}

    \item \textbf{核心子程序 (Subroutines)}：
    \begin{itemize}
        \item \texttt{CollectReadyTasks} 与 \texttt{CollectNearReadyTasks}：分别收集依赖已经满足的 task，以及可根据上游进度预测 ready 时间的 task。
        \item \texttt{PredictTokens(x, $\mathcal{S}$)}：根据 task 所属 session 的前驱输出特征以及当前节点 $v$ 自身的 Prompt 模板，推算出即将执行推理任务的预计输入 token 长度 $\hat{L}_{in}(x)$ 和输出 token 长度 $\hat{L}_{out}(x)$。
        \item $f_{GNN}(\dots)$：基于图神经网络（GNN）的资源预测器。它接收模型的静态图特征 $F(\mathcal{M}_v)$ 以及预测序列长度，输出估算的显存峰值 $M_{peak}(x)$ 与总推理耗时 $T_{infer}(x)$（涵盖 Prefill 和 Decode 阶段）。
        \item \texttt{SelectIdleInstance}：在模型资源池中选择与节点需求匹配且当前空闲的模型实例，用于立即执行 ready task。
        \item \texttt{SelectAccelerator}($\mathcal{K}, M_{req}$)：加速卡调度分配模块。基于请求的显存量 $M_{req}$，在物理加速卡集合 $\mathcal{K}$ 中根据特定分配原则（如最大适配、最小适配等）选出最合适的设备，否则返回 \texttt{NULL}。
        \item \texttt{EvictPolicy}($\mathcal{P}, M_{req}$)：空闲模型驱逐策略模块。当显存耗尽时，从资源池 $\mathcal{P}$ 中挑选出一组处于 $Idle$ 状态的模型实例作为受害者 (Victims) 以满足 $M_{req}$ 的显存诉求。本研究中的具体驱逐规则（如驱逐显存占用最大、驱逐空闲时间最长/LRU等）将作为可插拔策略在该函数内部实现。
        \item \texttt{LoadOrPrefetch}：在满足显存安全约束后加载模型；若 task 尚未 ready，则该加载行为表现为 prefetch。
    \end{itemize}
\end{itemize}
