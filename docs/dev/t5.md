# T5 变体生成接入说明

## 结论

T5 值得接入当前 `gnn_archs` 变体数据集生成流程，但必须作为独立文本模型族接入，
不能复用当前通用 text/BERT 构建分支。

理由：

- 当前数据已有 BERT encoder-only 和 GPT-2 decoder-only，T5 encoder-decoder 能补齐文本
  模型结构分布。
- T5 ONNX 图会引入 decoder self-attention、cross-attention、relative attention bias、
  shared embedding 等结构，对 `ONNX -> PyG Data -> GNN` 预测器有新增图形态价值。
- `T5ForSequenceClassification` 可以直接服务当前分类式 text pipeline，不需要改训练/推理
  结果模型。
- 本地实验证明 T5 支持 `full` 和 `architecture_only` ONNX 导出，随机初始化后的
  architecture-only ONNX 可用 ONNX Runtime 执行。

当前不能直接接入的原因：

- `is_text_model_name("t5") == True`，但 `build_variant_model()` 对通用 text 模型都会构建
  `BertForSequenceClassification`，所以 `t5` YAML 现在会静默生成 BERT。
- 当前 text fake batch 会随机生成所有 token，T5 sequence classification 要求每条输入里有
  一致数量的 `eos_token_id`，否则前向会失败。
- 当前 `build_example_batch()` 对所有 text 模型读取 `model.config.max_position_embeddings`，
  T5 使用 relative position embeddings，没有这个字段。
- 现有 `TEXT_MUTATION_TYPES` 和 `apply_text_config_mutations()` 是 BERTConfig 语义，不适合
  直接套给 T5Config。

推荐首批接入规模为 `216` 个变体：

```text
24 architecture shapes × 3 token profiles × 3 output class counts = 216 variants
```

如果训练和推理都开启，最终监控 CSV 约产生 `432` 行阶段记录。

## 资料调研结论

官方 Transformers T5 文档说明：

- T5 是 encoder-decoder Transformer。
- `T5Config` 的核心结构字段包括 `vocab_size`、`d_model`、`d_kv`、`d_ff`、
  `num_layers`、`num_decoder_layers`、`num_heads`、relative attention 参数、
  `dropout_rate` 和 `feed_forward_proj`。
- T5 使用 relative position embeddings，因此输入左右 padding 都可以。
- `T5ForSequenceClassification` 返回 `Seq2SeqSequenceClassifierOutput`，
  `logits` 形状为 `[batch_size, config.num_labels]`。
- `decoder_input_ids` 未传入时，T5 会从 `input_ids` shift 得到 decoder 输入，并使用
  `pad_token_id` 作为起始 token。

本项目当前锁定 `transformers==4.57.1`。本地源码和实验额外确认：

- `T5ForSequenceClassification.forward()` 用 `input_ids == eos_token_id` 提取句向量。
- 每条样本必须至少有一个 EOS，且 batch 内 EOS 个数必须一致。
- `feed_forward_proj="gated-gelu"` 会把 FFN 模块从 `T5DenseActDense` 换成
  `T5DenseGatedActDense`，属于真实结构变化。
- 无 EOS 时会触发：

```text
IndexError: index -1 is out of bounds for dimension 1 with size 0
```

## 已验证实验

所有实验只使用 `./.venv/bin/python -c ...` 和 `tempfile` 临时 ONNX 文件，实验结束后删除临时文件。

### 当前 builder 缺口

验证输出：

```text
is_text_t5 True True
current_builder_type BertForSequenceClassification True
```

说明当前 `base_model.name: t5` 会进入 text 路径，但实际构建 BERT。

### T5 前向和训练

使用最小 T5 配置：

```python
T5Config(
    vocab_size=512,
    d_model=64,
    d_kv=16,
    d_ff=128,
    num_layers=2,
    num_decoder_layers=2,
    num_heads=4,
    num_labels=3,
    pad_token_id=0,
    eos_token_id=1,
    decoder_start_token_id=0,
    use_cache=False,
    dropout_rate=0.0,
    classifier_dropout=0.0,
)
```

验证结果：

| case | result |
| --- | --- |
| no EOS input | `IndexError` |
| one EOS at last token | logits shape `(2, 3)` |
| loss backward | pass |
| params | `201,987` |

FFN 结构对照：

| config | FFN module | params |
| --- | --- | ---: |
| `d_model=128, d_ff=512, layers=4, proj=relu` | `T5DenseActDense` | 2,118,026 |
| `d_model=128, d_ff=512, layers=4, proj=gated-gelu` | `T5DenseGatedActDense` | 2,642,314 |

T5 fake text batch 必须这样生成：

```python
input_ids = torch.randint(2, vocab_size, (batch_size, sequence_length))
input_ids[:, -1] = eos_token_id
attention_mask = torch.ones((batch_size, sequence_length), dtype=torch.long)
```

### ONNX 导出和随机初始化

验证项：

| item | result |
| --- | --- |
| `architecture_only` export | pass |
| `full` export | pass |
| architecture-only initializers | `0` |
| architecture-only parameter inputs | `40` |
| randomized ONNX runtime inputs | `["input_ids", "attention_mask"]` |
| randomized ONNX valid EOS input | output shape `(2, 3)` |
| randomized ONNX no EOS input | ORT `InvalidArgument` |

ONNX 导出时出现两个 tracer warning：

- `sequence_length != 1` 被 trace 为常量分支。
- `len(torch.unique_consecutive(eos_mask.sum(1)))` 被 trace 为常量分支。

这两个 warning 对当前固定 shape 采样流程不是阻塞项。当前项目本来按固定
`example_input_shape` 生成 ONNX 和监控数据；运行时继续使用同样 shape 且每条样本一个 EOS 即可。

## T5Config 可变参数

推荐先纳入这些字段：

| 字段 | 作用 | 结构影响 |
| --- | --- | --- |
| `vocab_size` | token embedding 词表 | 是 |
| `d_model` | encoder/decoder hidden size | 是 |
| `d_kv` | 每个 attention head 的 key/query/value 维度 | 是 |
| `d_ff` | feed-forward 中间层宽度 | 是 |
| `num_layers` | encoder 层数 | 是 |
| `num_decoder_layers` | decoder 层数 | 是 |
| `num_heads` | attention head 数 | 是 |
| `relative_attention_num_buckets` | relative position bucket 数 | 是 |
| `relative_attention_max_distance` | relative position bucket 最大距离 | 是 |
| `feed_forward_proj` | FFN 结构，`relu` 或 `gated-gelu` | 是 |
| `dropout_rate` | 全局 dropout 概率 | 否 |
| `classifier_dropout` | 分类头 dropout 概率 | 否 |
| `layer_norm_epsilon` | LayerNorm epsilon | 否 |
| `initializer_factor` | 初始化缩放 | 否 |

固定字段：

```python
pad_token_id = 0
eos_token_id = 1
decoder_start_token_id = 0
use_cache = False
```

硬约束：

- `vocab_size > max(pad_token_id, eos_token_id, decoder_start_token_id)`
- `d_model > 0`
- `d_kv > 0`
- `d_ff > 0`
- `num_layers > 0`
- `num_decoder_layers > 0`
- `num_heads > 0`
- `relative_attention_num_buckets > 0`
- `relative_attention_max_distance > 0`
- `dropout_rate` 和 `classifier_dropout` 在 `[0, 1)` 内
- `feed_forward_proj in {"relu", "gated-gelu"}`
- fake batch 必须保证每条样本有且只有一个 EOS

建议默认 `d_kv = d_model // num_heads`，并要求推荐配置里的 `d_model % num_heads == 0`。
T5 本身不强制 `d_model` 被 `num_heads` 整除，但这个规则能让配置表更可读，也能让 head 维度
与 GPT-2/BERT 变体保持可比。

## 最小接入内容

### 配置模型

在 `src/gnn_archs/config.py` 增加 T5 配置块，并挂到 `VariantConfig`：

```python
class T5ConfigOverride(StrictModel):
    vocab_size: int
    d_model: int
    d_ff: int
    num_layers: int
    num_decoder_layers: int
    num_heads: int
    d_kv: int | None = None
    relative_attention_num_buckets: int = 32
    relative_attention_max_distance: int = 128
    dropout_rate: float = 0.0
    classifier_dropout: float = 0.0
    layer_norm_epsilon: float = 1e-6
    initializer_factor: float = 1.0
    feed_forward_proj: str = "relu"


class VariantConfig(StrictModel):
    ...
    t5_config: T5ConfigOverride | None = None
```

校验放在 T5 builder 内，避免污染 image / YOLO / BERT / GPT-2 路径。

### 构建分支

在 `build_variant_model()` 的 GPT-2 分支后、通用 text/BERT 分支前加 T5 分支：

```python
if normalize_model_identifier(spec.base_model.name) == "t5":
    from gnn_archs.t5_builder import build_t5_variant_model

    return build_t5_variant_model(spec)
```

如果后续希望支持 `google-t5/t5-small` 这类名字，需要把判断扩展为：

```python
normalized_name = normalize_model_identifier(spec.base_model.name)
if normalized_name == "t5" or normalized_name.startswith("t5-"):
    ...
```

首批 YAML 建议只用 `name: t5`，不引入 checkpoint 名称兼容。

### T5 builder

新增 `src/gnn_archs/t5_builder.py`：

```python
from __future__ import annotations

from typing import TYPE_CHECKING

import torch.nn as nn
from transformers import T5Config, T5ForSequenceClassification

if TYPE_CHECKING:
    from gnn_archs.config import ResolvedVariantSpec


def build_t5_variant_model(spec: ResolvedVariantSpec) -> nn.Module:
    if spec.mutations:
        raise ValueError("t5 variants do not support mutations")
    t5_config = spec.variant_config.t5_config
    if t5_config is None:
        raise ValueError("t5 variants require variant_config.t5_config")
    if spec.variant_config.target_output_classes is None:
        raise ValueError("t5 variants require target_output_classes")

    config_values = t5_config.model_dump()
    if config_values["d_kv"] is None:
        config_values["d_kv"] = config_values["d_model"] // config_values["num_heads"]

    config = T5Config(
        num_labels=spec.variant_config.target_output_classes,
        pad_token_id=0,
        eos_token_id=1,
        decoder_start_token_id=0,
        use_cache=False,
        **config_values,
    )
    validate_t5_config(config)
    return T5ForSequenceClassification(config)
```

`validate_t5_config()` 放在同文件：

```python
def validate_t5_config(config: T5Config) -> None:
    if config.d_model <= 0:
        raise ValueError("t5 d_model must be positive")
    if config.d_kv <= 0:
        raise ValueError("t5 d_kv must be positive")
    if config.d_ff <= 0:
        raise ValueError("t5 d_ff must be positive")
    if config.num_layers <= 0:
        raise ValueError("t5 num_layers must be positive")
    if config.num_decoder_layers <= 0:
        raise ValueError("t5 num_decoder_layers must be positive")
    if config.num_heads <= 0:
        raise ValueError("t5 num_heads must be positive")
    if config.vocab_size <= max(
        config.pad_token_id,
        config.eos_token_id,
        config.decoder_start_token_id,
    ):
        raise ValueError("t5 vocab_size must exceed special token ids")
    if config.feed_forward_proj not in {"relu", "gated-gelu"}:
        raise ValueError("t5 feed_forward_proj must be relu or gated-gelu")
    for field_name in ("dropout_rate", "classifier_dropout"):
        value = float(getattr(config, field_name))
        if value < 0 or value >= 1:
            raise ValueError(f"t5 {field_name} must be in [0, 1)")
```

### fake text batch

当前 `build_training_batch()` 和 `build_example_batch()` 需要在 text 路径里识别 T5：

```python
def is_t5_model(model: nn.Module) -> bool:
    return getattr(model.config, "model_type", None) == "t5"
```

T5 input 生成逻辑：

```python
def build_t5_input_ids(
    batch_size: int,
    sequence_length: int,
    vocab_size: int,
    generator: torch.Generator,
) -> torch.Tensor:
    input_ids = torch.randint(
        2,
        vocab_size,
        (batch_size, sequence_length),
        generator=generator,
    )
    input_ids[:, -1] = 1
    return input_ids
```

T5 不应执行 `max_position_embeddings` 校验。推荐把当前 text batch 分成两个小 helper：

- `build_bert_like_text_input_ids(...)`
- `build_t5_input_ids(...)`

这样 GPT-2/BERT 继续走现有逻辑，T5 只处理 EOS 约束。

### ONNX 导出

不需要 T5 专用 export wrapper。当前 `OnnxExportWrapper` 对 text 模型调用：

```python
outputs = self.model(input_ids=inputs[0], attention_mask=inputs[1])
```

这对 `T5ForSequenceClassification` 可用。关键是导出 batch 必须由 T5 helper 生成 EOS。

`architecture_only` 模式继续复用当前机制：

- runtime inputs: `input_ids`, `attention_mask`
- parameter inputs: T5 参数输入
- initializers: 空
- 随机初始化：复用 `write_randomized_onnx_model()`


## 数量规模探索

实验空间基于 GPT-2 文档中的 24 个 shape，但加入 T5 的 `feed_forward_proj` 覆盖。

推荐 token profiles：

| name | vocab | sequence | relative buckets | max distance |
| --- | ---: | ---: | ---: | ---: |
| `compact` | 512 | 24 | 16 | 32 |
| `short` | 1024 | 40 | 32 | 64 |
| `standard` | 2048 | 64 | 32 | 128 |

推荐 output classes：

```text
2, 10, 100
```

推荐规模分层：

| tier | 公式 | variants | 用途 |
| --- | --- | ---: | --- |
| smoke | `4 shapes × 2 token profiles × 2 output classes` | 16 | CI / 接入烟测 |
| pilot | `12 shapes × 3 token profiles × 3 output classes` | 108 | 首次 GPU 小批量验证 |
| recommended | `24 shapes × 3 token profiles × 3 output classes` | 216 | 首批正式数据生成 |
| recommended + batch sweep | `216 + 6 anchors × 4 batch sizes` | 240 | 216 稳定后补 batch 维度 |
| broad | `48 shapes × 3 token profiles × 3 output classes` | 432 | 后续需要更密 T5 覆盖时使用 |

首批不建议直接超过 `216`：

- T5 比 GPT-2 同 hidden/layer 组合更重，因为 encoder 和 decoder 都在图里。
- 当前 GNN 训练数据已经证明“少量但分布偏移的数据”会影响训练质量。
- T5 是新增模型族，先用均衡覆盖验证监控分布，再扩展 batch sweep 更稳。

| unique shapes | 24 |
| min params | 201,794 |
| median params | 5,572,179 |
| p90 params | 25,969,674 |
| max params | 68,318,308 |

参数量分布：

| bucket | variants |
| --- | ---: |
| `0-0.25M` | 6 |
| `0.25-1M` | 17 |
| `1-5M` | 82 |
| `5-20M` | 75 |
| `20-80M` | 36 |

结构类型分布：

| shape tag | unique shapes |
| --- | ---: |
| balanced | 13 |
| deep_narrow | 4 |
| shallow_wide | 3 |
| mlp_narrow | 3 |
| mlp_wide | 1 |

FFN 类型分布：

| feed_forward_proj | unique shapes |
| --- | ---: |
| relu | 18 |
| gated-gelu | 6 |

这些组合覆盖：

- 小参数模型
- 深窄模型
- 浅宽模型
- MLP 窄/宽对照
- `relu` 与 `gated-gelu` FFN 结构
- 中型 balanced
- 约 `68M` 参数以内的较大 T5 文本模型

首批暂不加入 encoder/decoder 非对称深度。T5 已经比 GPT-2 多 decoder cross-attention，
先保持 `num_layers == num_decoder_layers` 更利于和 GPT-2 结构集合对照。后续 broad tier
再加入例如 `encoder 6 / decoder 2`、`encoder 2 / decoder 6` 这种非对称结构。

## 推荐实施顺序

1. 增加 `T5ConfigOverride` 和 `VariantConfig.t5_config`。
2. 增加 `src/gnn_archs/t5_builder.py`，只支持无 mutation T5。
3. 在 `build_variant_model()` 增加 T5 专用分支。
4. 修改 text fake batch，使 T5 输入固定最后一位 EOS。
5. 修改 text example batch，避免 T5 读取 `max_position_embeddings`。
6. 增加 T5 builder、非法配置、pipeline、architecture-only ONNX 随机初始化测试。
7. 增加 `config/arch/t5_variants.yaml`，先落 `16` 个 smoke 变体。
8. smoke 通过后生成完整 `216` 配置。

最小可交付不需要实现 T5 mutation，也不需要改 `variant_expander.py`。这两个方向会扩大风险，
并且对首批数据生成没有必要。
