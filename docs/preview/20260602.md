# GNN 性能预测项目预览

## 当前定位

项目目标是用模型结构和运行环境特征，在真实运行前预测深度学习模型的运行时间、CPU、内存、GPU 利用率、SM 活跃度、SM occupancy 和显存等资源指标。当前主线是单一多目标 GNN predictor：从 ONNX 图构造 PyG `Data`，融合 node、edge、graph 级特征后做图级回归。

核心路径：

| 模块 | 作用 |
| --- | --- |
| `src/gnn_model/data/onnx_graph.py` | 从 ONNX 和 `onnx_tool` profile 提取节点、边、图级特征。 |
| `src/gnn_model/data/extract.py` | 从监控 CSV 构造图样本并划分 train/val/test。 |
| `src/gnn_model/models/predictor.py` | 多目标 GNN predictor，融合节点、边、图级状态。 |
| `src/gnn_model/models/fusion.py` | 使用 `TransformerConv` 更新节点、MLP 更新边，并融合 graph state。 |

当前输入特征：

| 层级 | 当前特征 |
| --- | --- |
| node | MACs、memory、params、input/output 数、attr 数、in/out degree、tensor shape 统计、op type embedding。 |
| edge | tensor bytes、rank、element count、source out-degree、target in-degree、tensor shape 统计。 |
| graph | phase、batch、sample count、GPU specs、参数输入统计、全图 MACs/memory/params、图规模和 activation 统计。 |

当前预测目标：

- `duration_sec_avg`
- `cpu_cores_p95`
- `memory_delta_gb_p95`
- `gpu_util_percent_p95`
- `gpu_sm_active_percent_p95`
- `gpu_sm_occupancy_percent_p95`
- `gpu_mem_used_mb_p95`

## 与现有工作的细化对比

| 工作 | 任务与场景 | 表示方式 | 数据与硬件 | 泛化口径 | 与当前项目的关系 |
| --- | --- | --- | --- | --- | --- |
| PerfSeer | 训练和推理性能预测，面向 DL 模型性能画像。 | ONNX 计算图，含 node/edge/global features。 | 53k+ 配置，RTX 3090，覆盖 VGG、GoogLeNet、ResNe(X)t、MobileNet、DenseNet。 | 公开主实验未看到完整模型族留出的主线描述。 | 任务最接近：同为 ONNX/GNN、多目标、训练+推理。当前项目覆盖 YOLO、文本和推荐模型，模型族更现代且更宽。 |
| DNNPerf | 训练时间和 GPU memory 预测。 | TensorFlow computation graph，含 node/edge/device features。 | 18,641 配置，TensorFlow v1.13.1，真实模型和 NAS 合成模型。 | seen family 内 70/10/20，并额外设置 UNSEEN family。 | 当前项目覆盖更多现代模型族；DNNPerf 的 family split 是另一种问题设定，不替代 row-random。 |
| DIPPM | A100 推理性能和 MIG profile 预测。 | TVM Relay graph + GraphSAGE + static features。 | 10,508 个 DL 模型，A100 40GB。 | 主实验 70/15/15 随机划分，另展示 seen/partially seen/unseen 示例。 | 与当前项目同为 GPU 图级多回归；DIPPM 聚焦 A100 inference/MIG，当前项目覆盖训练+推理和资源调度目标。 |
| PerfSAGE / EdgeDLPerf | 边缘设备推理 latency、energy、memory/SRAM 预测。 | TFLite graph，GraphSAGE 风格模型。 | 134,912 个 TFLite 模型，CPU/NPU/EdgeTPU。 | 80/20 随机 split，并区分 specialized/generalized design space。 | 同样采用随机划分作为主要评估口径之一；当前项目偏云端 GPU，任务目标和硬件环境不同。 |
| nn-Meter | 边缘推理 latency 预测。 | kernel-level decomposition。 | 26,000 CNN 模型，多种移动 CPU/GPU/VPU。 | 面向 kernel 和 runtime 执行计划。 | 与当前图级 GNN 回归互补：nn-Meter 更接近 kernel/runtime 层，当前项目更接近模型图和集群资源画像。 |
| BRP-NAS / Eagle | NAS latency 和 accuracy/rank 预测。 | NAS cell graph + GCN。 | NAS-Bench-201、LatBench 多设备。 | 固定 NAS 空间内采样，900 train/100 val/其余 test。 | 证明图模型适合固定搜索空间性能预测；当前项目的生成空间覆盖更多现代模型族。 |
| HELP | 硬件自适应 latency prediction。 | Meta-learning latency predictor。 | 多硬件 NAS latency 场景。 | unseen device few-shot adaptation。 | 与当前项目的硬件 specs 条件建模相关，但 HELP 的核心任务是硬件自适应。 |
| Habitat | 从已有 GPU 预测其他 GPU 的训练迭代时间。 | operation runtime scaling / MLP。 | ResNet-50、Inception v3、Transformer、GNMT、DCGAN，六种 GPU。 | 跨 GPU 预测。 | 与当前项目同样关注训练性能，区别在于 Habitat 主要建模跨硬件 scaling。 |
| NeuSight | 预测 unseen GPU 上训练/推理性能。 | kernel tile-level modeling。 | 多类 DL workloads 和新 GPU。 | unseen model、unseen GPU、二者同时未见。 | 与当前项目都关注训练/推理性能预测，但 NeuSight 更偏 kernel tile 和硬件可迁移。 |

### 当前项目的相对优势

- 模型族覆盖更宽：视觉分类、YOLO 检测、BERT/GPT-2/T5 文本模型、DeepFM/DCN 等推荐模型，而多数现有数据集集中在 CNN、NAS search space 或边缘模型。
- 目标更贴近集群资源调度：除 latency/time 和 memory 外，还预测 CPU cores、GPU util、SM active、SM occupancy、GPU memory P95。
- 使用真实监控标签：标签来自阶段窗口内 Prometheus/DCGM/容器指标聚合，不只是 FLOPs、params 这类 proxy。
- 统一训练和推理阶段：phase 进入 graph feature，同一 predictor 覆盖 training 与 inference。
- 单模型部署口径清晰：当前主线保留单一多目标 GNN，不依赖 stacker、校准器、后处理残差模型。
