### 检索结论

- 大多数性能预测工作没有把完整 `model_family` 留出作为主实验口径；更常见的是 row/config random split、固定 search space 内未见采样点、或跨硬件/跨设备泛化。
- DNNPerf 是最接近本次 DenseNet unseen 的明确例外：它把 AlexNet、VGG、OverFeat、ResNet-V2、GRU 五类模型作为 unseen model 测试集，训练集中不包含这些模型配置。
- TPUGraphs 和 NNIRP 不是普通 row split。TPUGraphs 按 graph 做 80/10/10 划分，验证和测试图不出现在训练中；NNIRP 使用 cluster-atomic split，保证同一 cluster 不跨 split。这两类协议更接近“结构单元隔离”，但仍不完全等同于本次按模型家族 DenseNet 全量留出。
- PerfSeer、DIPPM、PerfSAGE 的主结果都更接近随机样本/配置划分。它们报告的低 MAPE/WAPE 更适合理解为 seen-family 或 mixed-family distribution 下的拟合性能，不应直接拿来和 DenseNet family-holdout WAPE 对比。
- 相关工作也承认泛化困难，只是困难的切面不同：PerfSAGE 关注 design space 不均衡和泛化模型，TPUGraphs 明确指出 unseen graph 泛化受图多样性和不均衡影响，NeuSight 强调 unseen model 与 unseen GPU 下传统回归/MLP 误差会明显升高。

### 对本次 DenseNet 退化的解释

本次 `data/scaled_unseen_densenet` 是严格的 DenseNet family-holdout：train/val 中 DenseNet 数为 `0`，test 中 DenseNet 数为 `1,079`。这比 PerfSeer、DIPPM、PerfSAGE 这类主实验的 random split 更难，也更接近 DNNPerf 的 unseen model 评估、TPUGraphs 的 unseen graph 评估、NNIRP 的 cluster-atomic 评估。

因此，本次 test WAPE 从 train `0.083936`、val `0.095437` 升到 DenseNet test `0.222993`，不是简单的训练失败，而是评估协议切到了更严格的 out-of-family 泛化。val split 完全不含 DenseNet，best-val checkpoint 只优化 non-DenseNet 分布；它无法保证 DenseNet 的 concat-heavy topology、dense block、transition block 和资源利用率模式被正确外推。

与外部工作相比，本项目当前口径有三点需要特别注意：

- 不能把 row-random 或 config-random 论文指标直接作为 DenseNet unseen 的目标值。那些指标通常允许相似模型族或相似配置跨 split，泛化压力小很多。
- 如果后续论文或报告要强调“未见模型族泛化”，应把 row-random、variant/cluster split、family-holdout 三套结果并列报告；否则读者会混淆 seen-distribution 拟合能力和 true out-of-family 泛化能力。
- DenseNet test 目前只有 `densenet121`，所以该结果可说明“当前训练族到 densenet121 的外推困难”，但还不能代表所有 DenseNet 变体。更稳的 family 泛化结论需要 DenseNet121/161/169/201 或 DenseNet-like cluster 的非泄漏验证集。

## Family Holdout 退化机制分析

本节从本项目实现和本次数据出发，对 family holdout 场景下性能退化进行进一步分析。外部工作提供了问题框架：DNNPerf 指出 unseen model 预测需要更完整的计算图、operator scheduling、tensor liveness 和 framework runtime 因素；PerfSAGE 指出多 design space 下小分布会被大分布主导，且不同 op type 的数值特征可能相近但性能语义不同；TPUGraphs 和 NNIRP 则通过 unseen graph 或 cluster-atomic split 说明随机切分会高估泛化能力。本节不直接照搬这些结论，而是使用本项目数据和实现检查这些机制是否在 DenseNet holdout 中实际出现。

分析使用 `data/scaled_unseen_densenet`、`data/scalers_unseen_densenet/target_scalers.pkl` 和训练结果中的指标。统计代码均为 here-doc 临时代码，未写入仓库。

### 内插与外推的实验现象

train 与 val 是 non-DenseNet 内部随机切分，二者的结构分布和标签分布高度接近；test 则完全由 `densenet121` 组成。结果显示，模型在 train/val 上仍能保持较低 WAPE，但在 DenseNet test 上明显失效。

| split | family relation | original WAPE | node p50 | edge p50 | edge/node p50 | structural OOD distance p50 |
| --- | --- | ---: | ---: | ---: | ---: | ---: |
| train | non-DenseNet fit | 0.083936 | 453 | 548 | 1.161 | 2.793 |
| val | non-DenseNet interpolation | 0.095437 | 453 | 548 | 1.158 | 2.836 |
| test | DenseNet extrapolation | 0.222993 | 597 | 1,131 | 1.894 | 8.566 |

`structural OOD distance` 是仅用于分析的距离：用 op type ratio、`log1p(node_count)`、`log1p(edge_count)` 和 `edge/node` 构成结构向量，并用 train split 的 median/IQR 做 robust 标准化后计算到 train median 的欧氏距离。它不是训练指标，但能显示 test 样本相对 train 分布的位置。val 的距离分布与 train 接近，说明 val 是 interpolation；DenseNet test 的中位距离约为 val 的 `3.02x`，说明 family holdout 评估的是外推。

仅看节点数和边数的 min/max 会低估这个问题。DenseNet 的节点数并未超过 train 最大值，边数也没有超过 train 最大值；真正异常的是组合结构。train 的 `edge/node` p10/p50/p90 为 `0.982/1.161/1.237`，test 为 `1.854/1.894/1.978`。换言之，DenseNet 的图并不是更大，而是更稠密、更接近 concat-heavy 数据流。

### 图结构与 op type 分布差异

DenseNet test 的 op type composition 与 train/val 明显不同。train 与 val 的分布几乎一致，而 test 具有高 `op_other`、高 `op_conv`、高 `op_activation`、高 `op_join_split` 和高 `op_norm`，同时 `op_elementwise`、`op_constant`、`op_layout` 显著减少。

| op type | train ratio | val ratio | test ratio | test - train |
| --- | ---: | ---: | ---: | ---: |
| `op_norm` | 0.000021 | 0.000023 | 0.099589 | +0.099568 |
| `op_join_split` | 0.045809 | 0.044742 | 0.099589 | +0.053780 |
| `op_other` | 0.179086 | 0.181578 | 0.357315 | +0.178229 |
| `op_conv` | 0.119814 | 0.120518 | 0.192753 | +0.072939 |
| `op_activation` | 0.093368 | 0.093948 | 0.188276 | +0.094908 |
| `op_elementwise` | 0.222946 | 0.226838 | 0.030414 | -0.192532 |
| `op_constant` | 0.187913 | 0.183320 | 0.020177 | -0.167736 |
| `op_layout` | 0.061142 | 0.059375 | 0.001606 | -0.059536 |

这个差异直接触发本项目模型的弱点。当前 predictor 虽然使用 `op_type_ids` embedding 和 `structural_context_mode=basic`，但 `op_norm` 在 train 中只有 `190` 个节点，占 `8,987,001` 个训练节点的 `0.0021%`。DenseNet test 中 `op_norm` 有 `66,898` 个节点，占 `9.96%`。因此，`op_norm` 的 embedding、`op_norm` 相关 transition、以及它和 Conv/Activation/Join-Split 共同出现时的目标函数关系，在训练中几乎没有被学习。这个现象比普通“测试集分布不同”更具体：test 中一个重要的结构语义在 train 中近乎缺失。

`op_join_split` 的升高同样关键。DenseNet 的密集连接会反复将前序特征拼接后传给后续层，这会改变数据流 fan-in、edge density 和 activation liveness。当前特征有 degree、edge tensor bytes、shape logs、`peak_live_activation_bytes_log` 估计和 op transition 统计，但这些仍是压缩后的静态摘要，无法完整表达 DenseNet dense block 中跨层特征复用、concat 后 channel 增长、以及 runtime 对这些 concat/normalization pattern 的 kernel 选择。

### Global Feature 分布差异

本次训练使用的是 RobustScaler 后的 graph features。下表列出 test median 相对 train median 的最大偏移项；这些值可理解为 robust 标准化空间中的位置差异。

| graph feature | train IQR | train median | test median | test - train |
| --- | ---: | ---: | ---: | ---: |
| `max_tensor_dim_log` | [-0.980, 0.000] | 0.000 | -2.092 | -2.092 |
| `parameter_input_count` | [-0.671, 0.342] | -0.063 | 1.367 | +1.430 |
| `peak_live_activation_bytes_log` | [-0.495, 0.463] | 0.000 | -1.061 | -1.061 |
| `edge_count_log` | [-0.799, 0.404] | -0.003 | 0.630 | +0.633 |
| `graph_macs` | [-0.346, 0.636] | 0.085 | -0.426 | -0.511 |

这些 shift 说明 DenseNet 的外推不是“更大模型带来更大误差”这么简单。DenseNet test 的 `edge_count_log` 更高，但 `graph_macs`、`max_tensor_dim_log`、`peak_live_activation_bytes_log` 反而更低；`parameter_input_count` 又显著更高。这是一组训练集中不常见的联合特征：较高连接密度与较低 MAC/激活尺度同时出现。对于一个在 non-DenseNet 上训练的图级回归器而言，这类组合会削弱通过 FLOPs、params、activation bytes 等粗统计量外推出资源指标的可靠性。

这也解释了为什么 R2 和 WAPE 的解读会分裂。原始量纲 overall R2 仍为 `0.936431`，主要受显存目标的大尺度方差影响；但 normalized WAPE 达 `0.988954`，per-target R2 多数为负，说明模型在归一化多目标空间没有学到 DenseNet 的条件规律。

### 标签分布与条件分布差异

DenseNet test 的标签并非所有维度都落在 train 范围外。相反，部分 target 的中位数接近 train，中位显存甚至略低于 train。这说明退化不是单纯的 target range extrapolation，而是更典型的 covariate shift 与 conditional shift 叠加：相似的目标范围对应了不同的图结构条件，或相似的图级统计对应了不同的运行时行为。

| target | train p50 | val p50 | test p50 | test / train |
| --- | ---: | ---: | ---: | ---: |
| `duration_sec_avg` | 0.027848 | 0.028911 | 0.026778 | 0.962 |
| `memory_delta_gb_p95` | 1.439 | 1.443 | 1.899 | 1.320 |
| `gpu_util_percent_p95` | 58 | 59 | 37 | 0.638 |
| `gpu_sm_active_percent_p95` | 0.514 | 0.525 | 0.306 | 0.595 |
| `gpu_sm_occupancy_percent_p95` | 0.179 | 0.181 | 0.126 | 0.704 |
| `gpu_mem_used_mb_p95` | 2,905 | 2,793 | 2,767 | 0.952 |

模型的 test bias 与这一点一致。DenseNet 的 GPU util 和 SM 指标本身低于 train 中位数，但模型预测得更低：`gpu_util_percent_p95` target mean 为 `37.44`，prediction mean 为 `24.43`；`gpu_sm_active_percent_p95` target mean 为 `0.274`，prediction mean 为 `0.141`。显存则相反：target mean 为 `2,824 MB`，prediction mean 为 `3,392 MB`。这不是随机误差，而是系统性 conditional mapping 错误。

### 与本项目模型实现的关系

本项目当前实现有三个有利因素：它使用 ONNX 图而不是只用全局 FLOPs；它保留 node、edge、graph 三层特征；它还加入了 op type embedding 和 basic structural context。因此，本次结果不能简单归因于“模型太弱”。更准确的说法是：当前特征和架构足以支持 seen-family interpolation，但不足以支撑 DenseNet family extrapolation。

具体机制如下：

- `op_type_ids` 使用 15 类粗粒度类别，`op_other` 在 DenseNet test 中占 `35.73%`。这意味着大量 DenseNet 节点的性能语义被压入同一个兜底类别，模型无法区分其中可能非常不同的 runtime 行为。
- `op_norm` 在 train 中几乎缺失，却在 test 中占 `9.96%`。这会使 op embedding、op transition context 和目标函数关系都缺少训练信号。
- `structural_context_mode=basic` 聚合 op counts、op ratios、op metrics、op transition 和拓扑摘要，但它仍是图级统计摘要。DenseNet dense block 的长程复用、concat 后 channel 演化、activation 生命周期峰值和 kernel 选择并不一定能由这些统计量唯一决定。
- `GraphFusionLayer` 使用两层 `TransformerConv`，最终通过 mean/sum/max pooling 得到图级表示。对局部邻接和全局规模有效，但对 DenseNet 这种多层密集连接的长程依赖和 liveness path，容易丢失顺序和路径级信息。
- training 样本使用 ONNX forward graph 加 `phase_token_id` 表示训练/推理阶段，没有显式 backward graph、optimizer state、workspace、cuDNN/cuBLAS algorithm、operator scheduling、tensor liveness 的真实运行时信息。DNNPerf 认为这些 hidden runtime factors 对 unseen model 特别重要，本项目在这些维度上仍然是弱表示。
- checkpoint selection 只依赖 non-DenseNet val loss。由于 val 与 train 的结构分布几乎一致，best-val checkpoint 是 seen-family interpolation 的最优点，不一定是 DenseNet extrapolation 的最优点。本次 best epoch 为 `100`，但 test WAPE 比 20260604 明显更差，正好说明 val loss 不能可靠选择 family-holdout checkpoint。
- 训练 loss 是 normalized targets 上的加权 SmoothL1 平均风险，训练集中 DenseNet family 权重为零。该目标函数不会显式控制 unseen family worst-case risk，也不会对 op_norm/concat-heavy 子空间做不确定性惩罚。

Scaler 也需要单独说明。本次复用的 scaler 按既有记录使用全部 split 拟合，因此 test target 参与了 target scaler 拟合。这是协议上的 caveat，但它不能解释性能退化；如果有影响，它更可能让 normalized target 空间部分吸收 DenseNet test 的尺度信息。即便如此，test normalized WAPE 仍接近 `0.989`，说明错误主要来自模型条件外推，而不是归一化尺度未知。

### 论文口径结论

本实验揭示了行级或变体级随机切分与 family holdout 之间的本质差异。随机切分评估的是同一模型族或相似变体附近的 interpolation：train/val/test 共享 op composition、结构密度、runtime pattern 和 target conditional relationship。family holdout 评估的是 extrapolation：预测器必须从其他模型族中学习到可迁移的图结构与资源行为规律，并将其应用到一个从未出现过的结构族。

DenseNet holdout 的退化由以下证据共同支持：

- train/val 分布高度一致，val WAPE 仅从 train 的 `0.083936` 升到 `0.095437`。
- DenseNet test 的结构密度显著偏移，`edge/node` 中位数从 train 的 `1.161` 升到 `1.894`。
- 关键 op type 发生结构性变化，尤其是 `op_norm` 从 train 的 `0.0021%` 节点占比升到 test 的 `9.96%`。
- global feature 呈现不常见组合：更高边数、更高参数输入数量，但更低 graph MACs、max tensor dimension 和 peak live activation estimate。
- 标签分布不是简单的整体平移，显存和 duration 中位数接近 train，但 GPU util/SM 指标明显更低，说明错误来自条件关系变化。
- 预测偏差具有方向性：显存高估、GPU util/SM 低估、duration 高估，符合模型把 non-DenseNet 条件规律错误外推到 DenseNet 的模式。

因此，本次 DenseNet family-holdout 退化应表述为：当前 GNN predictor 在 seen-family distribution 上具备较好的拟合能力，但其结构表示和训练目标尚不足以支持未见模型族的稳健外推。要把结论推进到论文级别，需要同时报告 row-random、variant/cluster split 和 family-holdout，并把 family-holdout 作为单独问题处理，而不是把随机划分的低误差视为未见模型族泛化能力。

## 评估结论

- 该模型不是合格的 DenseNet unseen predictor：test WAPE `0.222993` 显著高于 row-random v3 复训水平，也显著差于 20260604 DenseNet unseen 记录。
- 主要风险不是训练失败，而是 checkpoint selection 与 unseen family 泛化不一致；val split 完全不含 DenseNet，因此 val loss 降低不能代表 DenseNet test 改善。
- 原始量纲 overall 被显存误差主导，但相对误差上 duration、GPU util、SM active、SM occupancy 都显示 DenseNet 泛化不足。
- 当前数据的 DenseNet test 只有 `densenet121`，不能推广为所有 DenseNet 变体族表现。
- 后续如继续做 family-holdout，应至少保留多 epoch checkpoints、报告 epoch-level test 曲线或构造非泄漏的 family-holdout validation；否则单个 best-val checkpoint 的结论不稳定。
