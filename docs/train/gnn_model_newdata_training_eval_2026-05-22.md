# GNN 预测器 v2 数据 shape-only 特征训练评估报告

## 执行摘要

本次实验基于你刚重新生成的 `data/scaled_v2` 和 `data/scalers_v2`，从头训练一次 GNN 预测器。训练时临时屏蔽 P0 中的 `op` 和 `recommender` 特征组，只保留 shape 特征工作，对应 `scripts/gnn_p0_feature_ablation.py --experiments shape_only`。

核心结果：

- 当前 `data/scaled_v2` split 为 `12,278 / 4,093 / 4,093`，总样本 `20,464`。
- 数据核验显示当前 v2 已不含 `dcn`、`edcn`、`dcnv2`，但仍包含 `deepfm` 共 `424` 条，其中 test split `96` 条。
- 本次屏蔽 `15` 个 node op-type 特征和 `48` 个 graph op/recommender 特征，edge 特征未屏蔽。
- best checkpoint 出现在 epoch `98`，best val loss 为 `0.093296`。
- test original-scale WAPE 为 `0.109083`，MAE 为 `67.048470`，RMSE 为 `429.044220`。
- GPU 指标中，`gpu_mem_used_mb_p95` WAPE 为 `0.108778`，`gpu_util_percent_p95` WAPE 为 `0.130675`，`gpu_sm_occupancy_percent_p95` WAPE 为 `0.171222`。

结论：在当前 v2 数据口径下，移除 `op/recommender` 特征、保留 shape 特征后，整体 WAPE 和 GPU 显存 RMSE 明显低于 2026-05-21 未移除推荐族群的数据结果。但该结果不能单独归因于特征屏蔽，因为数据分布同时发生了变化，尤其 `dcn/edcn/dcnv2` 已被移除。

## 运行命令

```bash
PYTHONPATH=src uv run python scripts/gnn_p0_feature_ablation.py \
  --data_dir data/scaled_v2 \
  --scaler_dir data/scalers_v2 \
  --output_dir output/gnn_model_newdata_20260522_shape_only \
  --experiments shape_only \
  --seeds 7 \
  --device cuda:0 \
  --batch_size 32 \
  --num_epochs 100 \
  --learning_rate 0.001 \
  --weight_decay 0.0001 \
  --hidden_dim 128 \
  --num_layers 2 \
  --num_heads 8 \
  --dropout_rate 0.1
```

可比性说明：

- 2026-05-22 的结果同时包含两类变量变化：数据集 family 分布变化，以及特征组屏蔽变化。
- 当前结果整体 WAPE 低于 2026-05-21 filtered v3，但 `gpu_util_percent_p95` 和 `gpu_sm_occupancy_percent_p95` 的 WAPE 高于 filtered v3。
- `gpu_mem_used_mb_p95` WAPE 从 filtered v3 的 `0.114192` 降到 `0.108778`，RMSE 从约 `1,290.219 MB` 降到 `1,050.863 MB`，主要受数据尾部下降和移除 `dcn/edcn/dcnv2` 影响。
- 因为 `deepfm` 仍在当前 v2 中，不能把本次实验视为“完全移除 deepfm/dcn/edcn 后”的结果。

## 判断

1. 当前 shape-only 配置可以稳定完成训练，best val loss 在后段继续下降，未观察到发散。
2. 在当前 v2 数据上，保留 shape、屏蔽 op/recommender 后，test original-scale WAPE 为 `0.109083`，属于近期实验中较好的整体结果。
3. GPU 显存指标改善明显，但更可能来自数据分布变化，特别是 `dcn/edcn/dcnv2` 移除后显存尾部下降。
4. `deepfm` 仍是当前 GPU 显存误差的最大加权来源，后续如果要验证“完全移除 deepfm/dcn/edcn”的影响，需要重新生成不含 `deepfm_monitor.csv` 的 v2 数据后再跑同一命令。
5. 单看特征组，本次不能证明 `op/recommender` 一定有害；它证明的是“当前 v2 数据 + shape-only”可达到较低整体 WAPE。要隔离特征影响，需要在同一份当前 v2 数据上补跑 `p0_all` 与 `no_shape` 对照。
