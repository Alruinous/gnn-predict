# 实验：GNN 资源预测相比静态公式与穷举剖析的精度—成本优势（2026-07-24）

> **读者须知**：本文写给论文作者。你**不需要读任何代码**，只需知道本项目（SagePilot）是一个把"LLM 智能体工作流"调度到多张异构 GPU 上的系统。下文会把这个实验涉及的每一个概念、每一种对比方法、每一个指标都用大白话解释清楚，并说明"为什么这样设计"。所有数字都可复现（命令见文末）。

---

## 0. 一段话看懂这个实验

SagePilot 调度器在做每一个决策（把哪个模型放到哪张卡、一张卡上并发几路请求、什么时候预加载/换出模型）之前，都要先"查一张表"——这张表告诉它"某模型在某卡、某 batch、某输入/输出长度下，会占多少显存、跑多久、加载多久"。**这张表怎么来，直接决定调度质量。** 本实验回答一个问题：**用一个图神经网络（GNN）读模型的计算图来预测这张表，值不值得？** 我们把它和两端对照——一端是"把每个配置都真跑一遍测出来"（穷举剖析，最准但极贵，是精度上限），另一端是"用一条物理公式硬算"（类似开源工具 llmfit，免费但粗糙）——外加几个常见的机器学习基线。**结论**：GNN 在最影响调度的"运行时长"上，精度逼近真实测量、比物理公式好近 10 倍；而拿到一条新预测的代价只有真实测量的约 1/2200；在"只允许少量真实测量"的公平预算下，GNN 明显强于把测量结果背下来的基线。我们也诚实指出：在"测量数据管够、且被测配置分布很密"时，一个简单的表格回归反而更准——这恰好说明真正的价值在于"用很少的真实测量就能泛化"，而这正是 GNN 的长处。

## 1. 背景：这个实验在系统里的位置

### 1.1 SagePilot 要调度什么
SagePilot 服务的是**多智能体 LLM 工作流**：一个会话（session）会经过多个节点，每个节点调用一个 LLM（例如先用小模型并行"自一致性"生成，再用大模型"精修"）。这些模型跑在一组**异构本地 GPU** 上——本实验涉及两种卡：**A100（80 GB 显存，带宽约 1935 GB/s）** 和 **V100（32 GB，约 900 GB/s）**。推理后端是 **vLLM**。

调度器要不停地做三类决策：
- **放置（placement）**：某个模型该加载到哪一种卡上？（大模型放不进 V100 就必须上 A100。）
- **批准入（batch admission）**：一张已在忙的卡上，还能不能再塞一路请求进去一起批处理？
- **生命周期（prefetch/evict）**：显存有限，什么时候提前把即将用到的模型预加载、什么时候把不用的换出，才能既不浪费又不卡顿。

### 1.2 每个决策都要先"查一张资源表"
上述决策全都依赖对资源的**事前估计**。系统内部维护一张**资源预测表**：对每一个"配置"给出三类关键数字——
- **峰值显存（peak VRAM）**：决定"这张卡装不装得下""还能不能再批一路"。
- **运行时长（run time）**：决定任务排序、完成时间估计（ETA）、以及预取/换出的时机。
- **加载时长、功耗**：次要信号（加载时长用于预取提前量，功耗用于能耗核算）。

> 一个**"配置"**就是一次具体的推理设定：**(模型, GPU 型号, batch 大小, 输入长度, 输出长度)**。

### 1.3 这张表可以怎么来？——这就是本实验的主题
填这张表有几条路，代价和精度天差地别：
1. **真跑一遍测出来（穷举剖析 profile）**：把每个配置都在真实 GPU 上执行、用监控测出真实数字。**最准**，是天然的"精度上限"，但**极贵**——每个配置都要占用 GPU 跑完整解码，且换个模型/换张卡就得全部重测。
2. **一条物理公式硬算（静态解析，llmfit 类）**：用"模型参数量 × 字节数 + KV 缓存公式 + 带宽"这类解析式估。**免费、瞬间出结果**，但忽略了框架开销、真实批处理动态等，**粗糙**。
3. **一个学习型预测器**：拿一部分测量数据训练一个模型去预测其余配置。本项目的方法是 **GNN**——它读入模型的**计算图**（算子拓扑）来预测资源，理念是"训练一次就能泛化到没测过的配置甚至新模型架构，无需为每个配置真跑一遍"。

**本实验就是要量化第 3 条（GNN）相对第 1、2 条的性价比。**

## 2. 为什么用"离线精度—成本"来评，而不是直接在系统上看效果

一个自然的想法是：直接把不同的资源表喂给调度器，跑真实负载，看谁的端到端延迟/吞吐更好、谁触发的 OOM 更少。**但这里有一个观测障碍**：推理后端 vLLM 自带很强的自我保护——它给每个模型独占整张卡、预留 98% 显存并**预分配 KV 缓存**，一旦请求过载就**抢占+重算**而不是直接崩溃。于是"单模型因显存估计不准而 OOM 崩溃"这个信号被 vLLM 兜住了，**GNN 预测的好坏很难在线上直接看出来**。

因此我们退一步，**在离线、不触碰运行时的前提下，直接度量每种预测方式的两件事**：
- **精度**：它对每个配置的资源估计，离真实测量有多远？
- **成本**：为一个新配置拿到一条估计，要付出多少代价？

这两件事是 vLLM 保护层**掩盖不掉的根因**：调度器的每个决策都只能和它查到的数字一样好；数字差，放置就会选错卡、批准入就会过/欠、预取换出就会抖动。把命题落到"精度 × 成本"，既干净又可复现。

## 3. 实验对象与"真值"从哪来

### 3.1 被评估的配置网格（2848 个）
我们覆盖服务侧会用到的解码（decode）配置：
- **模型**：Qwen3 系列 5 个规模——0.6B / 1.7B / 4B / 8B / 14B。
- **GPU**：A100、V100。
- **batch**：1、2、3。
- **输入长度**：1024 ~ 8192（11 个档位）。
- **输出长度**：128 ~ 4096（10 个档位）。

组合去掉大模型放不下的极端项后，共 **2848 个配置**。

### 3.2 "真值（ground truth）= profile"
对这 2848 个配置，我们**在真实 A100/V100 上逐一执行、用监控测出**：解码运行时长、峰值显存、功耗、加载时长。这张实测表就是本实验的**真值**，代号 **profile**。它是精度的"天花板"——任何预测器最多做到和它一样准。**代价**：把这张表建出来共花了 **64.4 GPU-小时**（平均每个配置约 81 秒的 GPU 时间），而且**换模型、换卡都得重来**。

### 3.3 评估协议：训练/留出划分
为公平比较，我们固定一个**确定性划分**（随机种子=7）：把 2848 个配置分成 **80% 训练池（2278 个）** 和 **20% 留出测试集（570 个）**。所有需要"学习/查表"的方法只能用训练池，**所有方法都在同一批 570 个留出配置上、对 profile 真值打分**。这样比较是同题同卷。

## 4. 参与对比的方法：逐一用大白话解释

下面每一种都是"给定一个配置，预测它的运行时长/峰值显存/功耗"。真值 profile 不算"方法"，是标尺。

| 代号 | 一句话原理 | 需要多少真实测量 | 直觉上强/弱在哪 |
|---|---|---|---|
| **profile**（真值/上限） | 直接真跑测出来 | 每个配置各测一次（全网格 64 GPU-时） | 定义上最准；但极贵、不可泛化 |
| **static**（静态解析，llmfit 类） | 一条物理公式硬算 | **0** | 免费；但忽略框架/动态，误差大 |
| **config-mean**（配置均值） | 用"该模型+该卡"已测配置的平均值 | 该 cell 的若干测量 | 极简；抹平了长度/batch 差异 |
| **nearest-profile**（最近邻） | 用"最相似的已测配置"的值 | 需要邻近配置已被测过 | 网格密时准；无邻居就失效 |
| **tabular**（表格回归 GBDT） | 梯度提升树，输入是标量特征 | 训练集越多越准 | 目标平滑时很准；**看不见计算图** |
| **gnn**（本项目方法） | 图神经网络读模型**计算图**来预测 | 少量锚点做校准 + 独立数据集预训练 | 少量测量即可泛化；点精度略糙 |

再展开解释关键的三种：

**static（静态解析，对标 llmfit / LIFE / BestServe 这类"公式法"）。** 它完全不看数据，只按物理量硬算：
- 权重显存 = 参数量 × 2 字节（fp16）。例如 14B 模型 ≈ 28 GB。
- KV 缓存 = 2（K 和 V）× 层数 × KV 头数 × 头维度 × 2 字节 ×（输入长度+输出长度）× batch。（Qwen3 用分组注意力 GQA，KV 头数=8、头维度=128。）
- 峰值显存 ≈ 权重 + KV + 一个固定的 CUDA/框架常驻开销（约 1.2 GB）。
- 运行时长（解码，受显存带宽制约）≈ 输出长度 ×（权重字节+KV 字节）/（GPU 带宽 × 0.55）。这里 0.55 是 llmfit 用的"带宽效率因子"。
- 加载时长 ≈ 权重字节 / 传输带宽。**这一项静态法几乎必错**：真实加载时间由框架初始化主导（约 24 秒），公式只按带宽算会给出不到 1 秒——正好暴露静态法的盲区。

**tabular（表格回归）。** 一个梯度提升决策树（GBDT），输入是几个**标量特征**：模型参数量、层数、GPU 带宽、batch、输入长度、输出长度；输出是各目标值。它**不知道模型的计算图长什么样**，只把资源当成这几个标量的函数去拟合。它是"有没有图结构"的对照实验（论文里的 predictor baseline 之一）。

**gnn（本项目方法）。** 一个图神经网络，输入是模型的**计算图**（每个算子是一个节点，带类型/形状/内存等特征），据此预测资源。它的卖点是**泛化**：在一个独立的算子基准数据集上预训练一次，再用**极少量**真实测量做校准，就能预测大量没测过的配置。本实验直接使用系统里已冻结的 GNN 预测表（其运行时校准只用了 50 条真实测量、显存校准用了 468 条）。

## 5. 评价指标：是什么、为什么选它

- **WAPE（加权绝对百分误差）** = Σ|预测−真值| / Σ|真值|。就是"总误差占总真值的比例"。选它而不选逐点百分误差（MAPE），是因为 MAPE 在真值很小时会爆炸、不稳定；WAPE 对量级鲁棒。**越小越准**，0 表示完美。
- **低估率** = 预测值 < 真值的配置占比。**为什么单独看它**：对"放置"而言，**低估显存是危险方向**——你以为装得下就放上去，实际爆了，导致加载失败/抢占。高估只是保守浪费，低估会出事。
- **最大低估** = 所有配置里"真值−预测"的最大值（显存以 GB 计）。衡量最坏情况能把显存低估到多离谱。
- **边际成本** = 为**一个此前没见过的配置**拿到一条预测，要付出的代价。profile 是真机执行的秒级 GPU 时间；gnn 是一次图前向的毫秒级 CPU 时间；公式/查表/GBDT 是微秒级。这是"性价比"的成本轴。
- **剖析预算（每 cell 锚点数）** = 允许每个"(模型,GPU)"用多少条真实测量。这是第 7 节要展开的关键旋钮。

## 6. 全量数据下的精度与成本

**这里让每个方法都用满 80% 训练池**（即"测量数据管够"的理想情形），在 570 留出配置上对真值打分。

### 6.1 精度（越小越准；显存最大低估越大越危险）

| 方法 | 运行时长 WAPE | 峰值显存 WAPE | 显存低估率 | 显存最大低估 | 加载 WAPE | 功耗 WAPE |
|---|---|---|---|---|---|---|
| **gnn** | **0.076** | 0.235 | 0.244 | 10.8 GB | 0.000 | 0.262 |
| static（llmfit） | 0.738 | 0.161 | **0.891** | **21.6 GB** | 0.996 | 0.489 |
| config-mean | 0.777 | 0.184 | 0.321 | 17.9 GB | 0.000 | 0.158 |
| nearest-profile | 0.109 | 0.066 | 0.300 | 6.4 GB | 0.000 | 0.050 |
| tabular（GBDT） | **0.033** | **0.012** | 0.505 | 2.4 GB | 0.000 | 0.021 |

**怎么读这张表：**
- **运行时长**是最影响调度（ETA/排序/预取）的信号。**GNN 的 0.076 紧贴真值，比静态公式的 0.738 好约 9.7 倍**；静态公式还把加载时长几乎全错（0.996）。
- **显存的低估方向才是安全关键**：静态公式 **89% 的配置低估显存、最坏低估 21.6 GB**——放置时极易选错卡；而 **GNN 系统性高估显存（偏安全一侧）**，低估率只有 24%。
- **但在纯精度的 WAPE 上，tabular 全面最好**（运行时长 0.033、显存 0.012）。原因见下节——这是本实验最重要的"诚实点"，不是缺陷而是关键发现。

### 6.2 成本（为一个新配置取一条预测）

| 方法 | 每配置边际成本 | 需要 GPU 吗 | 说明 |
|---|---|---|---|
| profile | **81.4 秒** | 是 | 真机执行；换模型/换卡须全量重跑；**全网格 = 64.4 GPU-小时** |
| **gnn** | **≈37 毫秒** | 否 | 图上一次前向，无需真实解码 |
| static | ≈34 微秒 | 否 | 解析公式 |
| config-mean | ≈38 微秒 | 否 | 查表 |
| nearest-profile | ≈1.4 毫秒 | 否 | 最近邻扫描 |
| tabular | ≈2.3 毫秒 | 否 | GBDT 前向 |

**GNN 取一条新预测的代价约为 profile 的 1/2200。** 但要注意一次性成本：GNN 缓存的校准用了约 **468（显存）+50（运行时）条真实测量**（一次性约 11 GPU-小时，且基础预测来自一个**独立**的算子基准数据集）；而 config-mean/nearest/tabular 的"准"依赖它们能看到的训练标签——那些标签本身就是那 64 GPU-小时的产物。**µs 级前向看着便宜，但它们的准确性其实是"先花 64 GPU-小时"换来的。** 这正是下一节要隔离的东西。

## 7. 实验的核心设计：为什么要做"剖析预算匹配"

### 7.1 全量比较为什么"不公平"
第 6 节里 tabular 全面最优，看似 GNN 输了。但想清楚"tabular 为什么准"：它把训练池里 2278 个真实测量几乎背了下来，而被评的 570 个配置又和训练配置**高度相似**（同一模型、相邻的长度/batch）。也就是说，**它的准来自"把整张表记住/插值"，而那张表本身要 64 GPU-小时**。同理，nearest-profile 靠"总能找到很近的已测邻居"。

所以"谁精度高"在**测量管够**时会偏向记忆型方法，但这恰恰回避了真正该问的问题：

> **如果只允许很少量的真实测量，谁预测得准？** —— 因为这直接决定了你要不要去付那 64 GPU-小时。

### 7.2 预算匹配协议
我们引入一个旋钮：**每个 (模型,GPU) 只允许 N 条真实测量（"锚点"）**。用这 N 条重建 config-mean/nearest/tabular，再在**同一批 570 留出配置**上打分。GNN 是固定的（它的运行时校准正好用了每 cell 5 条 = 50 条，作为参照点）；静态公式用 0 条（纯公式）。这样就能看出：**在相同的"真实测量预算"下，谁更准。**

### 7.3 结果：运行时长 WAPE 随锚点预算的变化

| 每 cell 锚点 | 总锚点数 | config-mean | nearest | tabular | **gnn（固定）** | static（0 锚点） |
|---|---|---|---|---|---|---|
| 1 | 10 | 0.977 | 0.977 | 0.839 | — | — |
| 2 | 20 | 0.941 | 0.657 | 0.920 | — | — |
| 3 | 30 | 0.818 | 0.478 | 0.821 | — | — |
| **5** | **50** | 0.839 | 0.452 | 0.456 | **0.076** | — |
| 10 | 100 | 0.774 | 0.337 | 0.218 | 0.076 | — |
| 20 | 200 | 0.806 | 0.265 | 0.141 | 0.076 | — |
| 50 | 500 | 0.780 | 0.191 | **0.079** | 0.076 | — |
| 参照 | 0 | — | — | — | — | 0.738 |

**这张表是本实验的核心图。怎么读：**
- **在 GNN 自己用的 50 锚点预算下（每 cell 5 条）**：GNN=**0.076**，而最好的记忆型基线 nearest/tabular≈**0.45**——**GNN 好约 6 倍**。config-mean 一直停在 ~0.80（太弱）。
- **tabular 要一路加到 ~500 条锚点（10 倍预算）**，运行时长 WAPE 才降到 0.079，**追平 GNN 的 0.076**。
- 换句话说：**GNN 用 1/10 的真实测量，达到了 tabular 需要满预算才能达到的运行时长精度。** 这就是"图预测器泛化"的价值所在，也是全量比较看不出来的。
- **诚实补充（显存维度）**：在显存上，tabular 只要 ≥100 锚点就反超 GNN（显存基本是"参数量、长度、batch"的平滑函数，很好插值）。所以 GNN 在**显存点精度**上并非最优——它的价值在于**偏安全的高估**和"少测量即泛化"，而系统对显存本就采用**校准上界**来做准入（见第 9 节与论文设计一致），并不依赖点估计当硬门。

## 8. 结论：这个实验证明了什么（诚实版）

1. **在最影响调度的"运行时长"上，GNN 决定性优于静态物理公式。** GNN 0.076 vs 静态 0.738（≈9.7×）；静态还把加载时长几乎全错、把显存 89% 低估（最坏 21.6 GB，放置的危险方向），GNN 则偏安全高估。
2. **GNN 的边际成本远低于穷举剖析上限。** 全网格 profile 要 64.4 GPU-小时；GNN 取一条新预测约 37 毫秒、无需 GPU 执行，约为 profile 的 1/2200。
3. **相同真实测量预算下，GNN 的泛化优于记忆/表格基线。** 50 条锚点时 GNN 运行时长 WAPE 0.076，最好基线 ≈0.45（≈6×）；tabular 要 ~500 条（10× 预算）才追平。
4. **诚实边界**：当真实测量管够、且被测配置分布很密时，一个简单的表格回归在纯 WAPE 上会反超 GNN——这不削弱上述三点，反而印证"无限剖析下记忆最优，但那正是 64 GPU-小时的代价"。有意义的工作区间是**有限剖析预算**，此处 GNN 占优。GNN 在**显存点精度**上不如 tabular，其价值是"偏安全的高估 + 少测量即泛化"，与论文"预测用于排序、校准上界用于准入"的设计一致。

## 9. 与论文的对应关系（给写作者的接口）

- 直接支撑 **RQ1（预测器精度）**：论文列出的 predictor 基线正是"静态 size/bandwidth 公式、nearest-profile、configuration means、tabular regressor"，本实验一一实现并给出与论文同量级的运行时长 WAPE（GNN 0.076 vs 论文 0.066）。
- 直接支撑 **RQ5（预测开销）**：给出"生成一条预测的边际成本"与"建全表的 GPU-小时"，量化 GNN 相对穷举剖析的成本优势。
- 印证**动机与安全设计**：论文强调"平均精度不足以做准入，显存会被低估（论文数据 49.9% 低估、最坏 24.3 GB）"。本实验里静态公式 89% 低估、最坏 21.6 GB，方向一致；GNN 偏安全高估——支撑论文"用点估计排序、用校准上界做准入"的路线，而非拿原始点估计当硬门。
- **可直接引用的句子模板**："在服务网格上穷举剖析需 64 GPU-小时且换硬件即失效；GNN 在相同约 2%（50/2848）的真实测量预算下，运行时长预测的 WAPE 比最好的记忆型基线低约 6 倍，同时把取一条新预测的边际成本从 81 秒降到 37 毫秒。"

## 10. 有效性威胁与局限（务必在论文中保留）

- **稠密同分布网格偏向记忆型方法**：被评配置与训练配置高度相似，nearest/tabular 因此很强；这也是我们引入"预算匹配"来隔离泛化的原因。真正的**跨架构外推**（对全新模型族）本实验未覆盖。
- **无法做真正的"留一个模型架构"评估**：现有 GNN 缓存是在全部 5 个模型上训练得到的，要做"留出整个架构"的外推必须**重训 GNN**（需要训练管线+GPU），超出本轮"离线、不重训"的范围。预算匹配是它的离线近似。
- **在线端到端未验证**：把不同资源表喂进真实调度器比 p95 延迟/吞吐/换出抖动，需要 A100+V100 的 Ray 集群；本轮范围限定离线。
- **加载时长对 GNN 是"继承"的**：GNN 缓存的加载时长直接沿用了 profile 值（故其加载 WAPE≡0），因此加载维度不体现 GNN 能力；GNN 真正预测的是运行时长/显存/功耗。
- **静态基线不是稻草人**：它带了一个校准过的固定框架开销常数，是一个诚实的"公式法"实现，而非故意做差。

## 11. 复现方式

```bash
# 在仓库根目录；WT 指向本实验代码所在（合并后即为仓库根）
WT=.
# 1) 由 profile 真值表生成四个基线的预测表（static/config_mean/nn/tabular）
PYTHONPATH=$WT/src uv run python $WT/scripts/workflow/build_baseline_prediction_caches.py \
  --profile-cache cache/profile/predictions.yaml \
  --cache-config config/workflow/cache.yaml --out-dir cache
# 2) 以 profile 为真值，对 gnn 与四个基线评精度+成本，并做预算扫描
PYTHONPATH=$WT/src uv run python $WT/scripts/workflow/eval_prediction_caches.py \
  --profile-cache cache/profile/predictions.yaml --cache-dir cache --out-dir output/cache_eval
```

**产物**：
- `output/cache_eval/tables.md`：全量精度表 + 成本表。
- `output/cache_eval/budget_sweep.csv`：预算扫描（本文第 7.3 表的数据源）。
- `output/cache_eval/accuracy_cost.json`：全部数值（含按 模型×GPU 的分层）。
- `output/cache_eval/pareto.csv`：精度—成本散点数据（可直接画 Pareto 图）。
- `cache/{static,config_mean,nn,tabular}/predictions.yaml`：四个基线的完整预测表（与 profile/gnn 同格式，可被调度器直接消费）。

> 说明：真值表 `cache/profile/predictions.yaml` 与 GNN 表 `cache/gnn/predictions.yaml` 是系统里已存在的产物；本实验只新增了四个基线表与评估脚本，未改动任何调度运行时代码。

## 12. 术语速查

| 术语 | 含义 |
|---|---|
| 配置（configuration） | 一次具体推理设定：(模型, GPU, batch, 输入长度, 输出长度) |
| profile（剖析） | 把每个配置真跑一遍测出的资源表；本实验的**真值/精度上限** |
| static / llmfit 类 | 用物理公式（参数量×字节 + KV + 带宽）硬算的静态预测 |
| config-mean / nearest-profile | 用"该模型+卡的均值"或"最相似已测配置"来预测（记忆/查表型） |
| tabular（GBDT） | 用标量特征训练的梯度提升树，**不看计算图** |
| gnn | 读模型**计算图**的图神经网络，本项目方法 |
| WAPE | 加权绝对百分误差 = Σ|预测−真值|/Σ|真值|，越小越准 |
| 低估率 / 最大低估 | 预测<真值的占比 / 最坏低估幅度；显存低估是放置的危险方向 |
| 边际成本 | 为一个新配置取一条预测的代价（GPU-秒 / 毫秒 / 微秒） |
| 锚点预算 | 每个 (模型,GPU) 允许使用的真实测量条数（第 7 节的核心旋钮） |
