# Workflow 实验结果索引（20260626）

本文记录 20260626 前后 workflow 实验的主结论。详细 JSONL、stderr 和临时配置以实际运行目录为准。

## GSM8K / MBPP

已有实验对比过 direct 32B、weak workflow 和 strong workflow。

结论：

- weak workflow 在 GSM8K 和 MBPP 上质量都不足，不能证明小模型 workflow 接近大模型。
- strong workflow 在 GSM8K 上接近 32B direct，但更慢。
- strong workflow 在 MBPP 上超过 32B direct，但耗时明显更高。
- 这组结果说明 workflow 有任务价值，但不宜默认更快。

可支持的说法：

```text
强 workflow 在部分任务上能接近或超过 direct 的质量，但成本需要调度控制。
```

当前不适合支持的说法：

```text
任意小模型 workflow 都接近大模型。
workflow 通常更快。
```

## QMSum / Multi-News

后续分层 pilot 可能比全量长跑更有参考价值。

QMSum：

- strong 6-way workflow 质量最好。
- strong workflow 平均时延低于受输入上限限制的 direct 32B。
- 这个任务适合继续做 workflow 调度优化。

Multi-News：

- direct 32B 是当前有效设置里表现最好的路径。
- strong 6-way 明显强于 weak，但仍低于 direct，且更慢。
- direct 在更长输入上限下出现过 OOM，说明 workflow 仍可能作为资源受限备选。

## 对调度的启发

当前实验更支持先看“路径选择”，而不是固定一种 workflow。

调度器后续可以考虑：

- direct、weak、strong 的路径选择。
- 输入长度和任务类型。
- chunk barrier。
- merge / refine 串行尾部。
- 显存和 OOM 风险。
- judge 成本是否计入实验 wall time。

weak workflow 更适合作为低成本候选，不宜绕过质量约束。
