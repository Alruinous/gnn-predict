# Workflow 运行设计探索

当前 Workflow 配置只描述 DAG、节点模型先验和运行输入参数。执行层以 LangGraph 为主，不再维护一套 workflow 自己的 DAG runner。

当前抽象是：

```text
WorkflowConfig
  -> LangGraph ReAct agent
  -> BaseToolNode
  -> NodeHandler
  -> WorkflowNodeResult
```

LLM 主节点通过 LangGraph `create_react_agent` 组成 ReAct 智能体。工具节点由 `BaseToolNode` 包装成 LangChain tool，tool name 与 workflow node name 一一对应。LangGraph 负责工具调用流程，`BaseToolNode` 只负责准备输入、调用 `NodeHandler`、整理 `WorkflowNodeResult`。

## 核心判断

- `serial`、`parallel`、`adaptive` 是保留的运行模式概念，但当前不实现独立 DAG runner。
- Workflow 边只表达静态依赖和配置关系，不承担 tensor 或业务数据流传递。
- LLM 是否调用某个工具由 LangGraph ReAct 流程和工具 description 决定。
- 节点执行失败是工具调用结果的一部分，由 `WorkflowNodeResult` 表达。
- `adaptive` 后续接入 GNN 预测器时，应优先作为工具选择、资源估计或调度元数据，不提前引入自定义 scheduler。

## Tool Node

工具节点的稳定边界是：

```text
tool.invoke({task, input_path, payload})
  -> BaseToolNode.prepare_node_input()
  -> NodeHandler.run(node, context)
  -> BaseToolNode.format_node_output()
```

`BaseToolNode` 不做模型推理，也不实现调度。具体 CV、NLP 或其他小模型工具节点可以覆盖输入准备或输出整理方法；真实模型部署、加速卡执行、远程调用或资源采集都放在 `NodeHandler` 实现中。

## Handler 边界

`NodeHandler` 不绑定具体执行后端：

```text
run(node, context) -> metadata
```

当前只保留 `NodeHandler` 协议。调用方必须提供真实 handler 或自定义 `tool_nodes`，不能用空实现让工具调用假成功。

后续可按实际需要增加：

- `GnnArchsNodeHandler`：把 workflow tool node 映射到现有模型 workload。
- `SubprocessNodeHandler`：用外部命令运行节点。
- `KubernetesNodeHandler`：提交 Pod 或 Job。

这些实现不应改变 workflow 配置格式，也不应重新引入本地 DAG runner。

## 结果结构

单个工具调用返回 `WorkflowNodeResult`：

```text
node_name
status
started_at
ended_at
duration_sec
error_type
error_message
metadata
```

`status` 保留完整生命周期状态：

```text
pending
running
succeeded
failed
skipped
```

当前工具调用结果主要产出 `succeeded` 或 `failed`。`pending`、`running`、`skipped` 保留给后续事件流、UI、外部执行后端或显式跳过语义。

## 与现有项目的关系

现有 `gnn_archs` 更像“变体生成、训练/推理/ONNX/监控样本采集”链路，不是通用 DAG runtime。Workflow 不应复用 `variant_runner.run_variant()` 当成图节点调度器。

更合适的路线是：

- 用 workflow YAML 描述 agent/tool 节点和 description。
- 用 LangGraph 执行主 LLM 的工具调用流程。
- 用 `NodeHandler` 把单个 tool node 映射到可运行 workload。
- 后续把 GNN predictor 作为资源估计或元数据能力接入。

## 不要过度设计

不要在当前阶段加入：

- workflow 自己的 serial/parallel DAG runner。
- 多后端执行插件系统。
- GPU 显存装箱。
- 自动 retry。
- checkpoint/resume。
- 动态修改 DAG。
- 节点间真实数据传递。
- Kubernetes/Ray 绑定。
- GNN predictor 强依赖。
